# Тестовый сервер

Стенд запускается на Ubuntu с Docker Compose через `compose.production.yml` и Caddy. Доступен по домену, заданному в `APP_DOMAIN`. Caddy выпускает и обновляет HTTPS-сертификат после появления публичной A-записи домена. Наружу открыты только 80 и 443; PostgreSQL, Redis, API и сервис оценки доступны внутри Docker-сети.

В `/opt/fsp-hack/.env` хранятся `APP_DOMAIN`, `POSTGRES_PASSWORD`, `JWT_SECRET` и ключ выбранного LLM-провайдера. Для OpenRouter нужны `LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`; для совместимого API — `LLM_PROVIDER=listapi`, `LIST_API_KEY` и `LIST_API_MODEL` (проверенная модель `gpt-5.6-sol`). Файл не входит в Git и должен быть доступен только владельцу сервера. Закрытый банк заданий лежит в `/opt/fsp-hack/private-bank/assessment-bank.json` и тоже не входит в Git. Compose сохраняет базу, фотографии и сертификаты в именованных томах.

Для обновления после коммита запустить из PowerShell `./deploy/update.ps1`. Скрипт переносит на сервер только отслеживаемые файлы текущего коммита, пересобирает изменившиеся образы и показывает состояние контейнеров. `.env`, закрытый банк и тома при обновлении не удаляются. Перед запуском следует подтянуть нужный коммит локально; незакоммиченные изменения скрипт не переносит.

Проверка после обновления: `https://<APP_DOMAIN>/api/v1/health` возвращает `{"status":"ok"}`. Публичный `/api/v1/system/seed` в этом окружении отключён.
