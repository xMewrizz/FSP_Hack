# ФСП.Карьера

Прототип платформы для подбора ИТ-специалистов по подтверждённым навыкам. Работодатель описывает потребность, получает кандидатов из подходящих категорий и сам отправляет приглашение с условиями и зарплатой. Категорию кандидата определяют опрос и тест; результаты ФСП могут дополнить профиль.

Проект выполняется по [ТЗ ФСП](docs/00-tz-keypoints.md). Репозиторий пока содержит **каркас**, а не готовый MVP. Сквозной сценарий, интерфейс, хранение данных, авторизация и подбор ещё не реализованы.

## Что есть сейчас

| Компонент | Состояние |
|---|---|
| Backend | FastAPI с `/api/v1/health` и `/docs-health`; предметных API нет |
| ML-сервис | FastAPI с `/health` и тремя заглушками; тестирование и скоринг не работают |
| Frontend | Только Dockerfile; исходников React и `package.json` нет |
| PostgreSQL и Redis | Описаны в `docker-compose.yml`, прикладные схемы и миграции отсутствуют |
| Документация | Описывает проектируемое решение и бэклог; результатов валидации пока нет |

`docker compose up --build` сейчас не собирает приложение: сборка frontend требует отсутствующий `package.json`. Подробности — в [инструкции по запуску](docs/03-api-and-run.md).

## Сценарий MVP

1. Кандидат регистрируется по email, заполняет профиль, выбирает специализацию и предполагаемый грейд.
2. Кандидат проходит тест на выбранный уровень. По результату получает категорию «специализация + подтверждённый грейд». Если уровень не подтверждён, система предлагает тест на уровень ниже, но не понижает грейд автоматически.
3. Работодатель описывает потребность и видит подходящие категории и кандидатов. Ранжирование опирается на результаты теста и подтверждённые достижения ФСП; причина рекомендации видна в карточке.
4. Работодатель отправляет приглашение с описанием предложения, способом связи и диапазоном зарплаты в рублях. Контакты кандидата раскрываются после принятия приглашения либо его самостоятельного отклика.

В ТЗ также предусмотрены профиль компании, поиск по банку кандидатов, статусы приглашений, настройки приватности и профиль кандидата без истории ФСП. Публикация вакансий и самостоятельные отклики желательны, но не обязательны для MVP. Короткие задания от работодателя тоже отнесены к дополнительным возможностям.

## Принятый технический подход

- Backend: Python 3.12, FastAPI, PostgreSQL 16, Redis.
- Frontend: планируются React, Vite и Tailwind CSS. Исходники ещё не добавлены.
- ML-сервис: отдельный Python API для разбора резюме, вариантов заданий и подбора. Qwen и эмбеддинги рассматриваются как вспомогательные инструменты; прохождение теста и базовый подбор не должны зависеть от доступности языковой модели.
- Интеграция с ФСП: на демо используется локальный набор тестовых достижений. Привязка учётной записи через Keycloak/OIDC и получение достижений из реестра — разные будущие интеграции; API реестра организаторы не предоставили.

Подробности: [архитектура](docs/01-architecture.md), [тестирование и подбор](docs/02-testing-matching.md), [план валидации](docs/04-validation-dataset-model.md).

## Локальная проверка текущего каркаса

При установленном Python:

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

После запуска доступны `http://localhost:8000/api/v1/health` и `http://localhost:8000/docs`. ML-сервис можно запустить отдельно на порту 8001 после установки его зависимостей. Эти команды проверяют только каркас API. Полный запуск через Docker Compose станет возможен после добавления исходников frontend и реализации сервисов.
