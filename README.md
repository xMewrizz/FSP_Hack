# ФСП.Карьера

Прототип платформы для подбора ИТ-специалистов по подтверждённым навыкам. Работодатель описывает потребность, получает кандидатов из подходящих категорий и сам отправляет приглашение с условиями и зарплатой. Категорию кандидата определяют опрос и тест; результаты ФСП могут дополнить профиль.

Проект делаем по [ТЗ ФСП](docs/00-tz-keypoints.md). Интерфейс и основные API запускаются вместе через Docker Compose.

## Что есть сейчас

| Компонент | Состояние |
|---|---|
| Backend | API авторизации, профилей кандидата и компании, публикаций и откликов на вакансии, приглашений, подбора, тестирования, менторской сети и HR-команд. Командные статусы/заметки хранятся отдельно от профиля кандидата |
| ML-сервис | Помогает разобрать потребность и оценивает развёрнутые ответы. При сбое модели ответ сохраняется для повторной автоматической проверки; грейд без оценки не присваивается |
| Frontend | Кабинеты кандидата и работодателя, адаптивный банк и подбор, тесты и история результатов, HR-команда и карточки кандидатов, задания работодателей, отклики, диалоги и отдельный раздел поиска ментора |
| PostgreSQL и Redis | Запускаются через Compose; PostgreSQL проходит проверку готовности |
| Документация | Описаны API, тестирование и подбор, техническая проверка тестов и [сравнение сортировок](docs/09-ranking-review.md); качество ранжирования на реальных людях ещё не подтверждено |

Демо-режим использует связанный локальный набор кандидатов, откликов, приглашений, тестовых результатов, наставников и диалогов; эти данные не являются записями production. На запущенном Compose проверен путь от регистрации до принятия приглашения. В последнем замере B-31 время ответа P95 составило 315 мс при пороге 500 мс. Команды запуска приведены в [инструкции](docs/03-api-and-run.md).

## Реализованные возможности

- Паук-маскот сопровождает кабинеты кандидата и работодателя, экран тестирования и грейда: карта компетенций показана как уникальная паутина, а пройденные навыки — как новые нити. Иллюстрации лежат в `frontend/src/assets/`; на обзоре кандидата отдельная галерея не показывается.
- Кандидат управляет профилем и видимостью, указывает навыки, опыт, хобби и образование; может пройти тесты, видеть историю и результаты, откликаться на вакансии и принимать предложения.
- Имя и фамилия принимают буквенные написания на кириллице и латинице, пробелы, дефисы и апострофы. Простая проверка отклоняет цифры, спецсимволы, повторяющиеся знаки и распространённые клавиатурные наборы; это проверка ввода, а не подтверждение личности. Email проверяется по формату, телефон — по допустимым символам и количеству цифр.
- Кандидат и работодатель видят процент заполненности профиля и подтверждение email. Процент учитывает заполненные поля, не подтверждает личность и не означает, что телефон проверен.
- Кандидат может перейти на [официальный сайт ФСП](https://fsp-russia.ru/) и прикрепить к профилю PDF-дипломы олимпиад (до 10 МБ каждый). Вложения сохраняются в профиле, но автоматически не проверяются и не подтверждают грейд.
- До доступа к материалам теста кандидат подтверждает конфиденциальность. Задания, ответы и решения закрыты от показа до согласия; экран явно запрещает распространять тестовые материалы и скриншоты.
- Работодатель публикует и редактирует вакансии, рассматривает отклики, отправляет персональные приглашения и общается с кандидатами. Контактные данные по приглашению открываются после согласия кандидата.
- Банк кандидатов поддерживает поиск по имени, навыкам, специализации, грейду, формату, городу, образованию, курсу и возрастному диапазону. Подбор показывает релевантность и объяснение совпадений; результаты навыков отображаются на подписанных радарах.
- Работодатель создаёт задания для выбранной специализации и диапазона грейдов, задаёт условие и критерии, добавляет ссылки и файлы. Он просматривает решения, выставляет баллы и комментарий; после оценки может пригласить кандидата, если тот разрешил связаться. Кандидат отправляет текстовый ответ, ссылки и вложения, а также видит оценку и обратную связь.
- Выполненное задание считается успешным при результате выше 75%. Дата последнего успешного решения используется для статуса активности кандидата: «Активен», «Недавно активен», «Устаревает» или «Не активен».
- HR-команда объединяет рабочее пространство компании: владелец приглашает тимлидов и HR, тимлид приглашает HR, а тимлид/владелец назначает HR права просмотра и редактирования по отдельным вакансиям.
- Внутренняя карточка кандидата содержит этап подбора, статус поиска контакта, ручной статус проверки СБ, заметки и обсуждение, доступные участникам HR-команды.
- Этапы найма включают оффер, онбординг, работу с ментором и найм. Работодатель видит отклики по каждой своей вакансии и может переписываться с откликнувшимися кандидатами в «Диалогах».
- Кандидат может отдельно открыть поиск ментора, найти специалистов по навыку с подтверждённым более высоким грейдом, отправить запрос и продолжить общение в диалогах. Для видимости в каталоге ментор включает доступность наставничества; контакты открываются после принятия запроса.
- Кандидат видит число отправленных откликов и запросов наставникам. Менторская сеть поддерживает каталог, запросы, принятие и переписку.
- В офлайн-демо доступны синтетические профили, заявки, примеры истории тестов, наставники и диалоги; для дипломов в демо сохраняются только названия файлов. Демо-режим не заменяет серверную базу и не синхронизируется между устройствами.

## Ограничения и интеграции

- Подтверждение ФСП ID и получение официальных достижений из реестра не подключены: на демо доступны только тестовые записи. PDF-дипломы прикрепляются к личному профилю, но не проходят автоматическую проверку. Кнопка Keycloak на экране входа — демонстрационная имитация входа в локальный демо-кабинет; реальная интеграция Keycloak/OIDC не подключена.
- Заполнение профиля и резюме доступно, однако автоматический разбор резюме зависит от настроенного ML-сервиса и не должен считаться источником подтверждённых сведений.
- Тестовые задания и пороги требуют валидации на реальных участниках; качество ранжирования также не подтверждено реальными метриками.
- Стадия проверки безопасности в HR-карточке — ручной командный статус, а не подключённая проверка или автоматический вердикт.
- Перед развёртыванием на реальных данных нужно настроить секреты, хранилище, резервное копирование и интеграции отдельно от демо. Подробности — в [архитектуре](docs/01-architecture.md), [правилах тестирования и подбора](docs/02-testing-matching.md) и [плане валидации](docs/04-validation-dataset-model.md).

## Принятый технический подход

- Backend: Python 3.12, FastAPI, PostgreSQL 16, Redis.
- Frontend: React, Vite и Tailwind CSS; исходники добавлены.
- ML-сервис: отдельный Python API. В режиме описания задачи он обращается к выбранной модели и предлагает навыки с важностью 1–5. Явные грейд, зарплата и формат извлекаются отдельно; работодатель проверяет всё перед сохранением. Если модель недоступна, остаётся ручное заполнение. Базовые наборы Backend и Data Science / ML включают развёрнутые задания с модельной оценкой. При сбое модели кандидат может повторить проверку сохранённого ответа; подбор уже подтверждённых кандидатов продолжает работать.
- Интеграция с ФСП: на демо используется локальный набор тестовых достижений. Привязка учётной записи через Keycloak/OIDC и получение достижений из реестра — разные будущие интеграции; API реестра организаторы не предоставили.

Подробности: [архитектура](docs/01-architecture.md), [тестирование и подбор](docs/02-testing-matching.md), [план валидации](docs/04-validation-dataset-model.md). Сравнение формулы с простой сортировкой — в [отчёте B-14](docs/09-ranking-review.md); отдельный учебный эксперимент с моделями — в [отчёте Романа](docs/15-ranking-model-experiment.md).

## Локальная проверка

Для backend используется `uv`:

```powershell
cd backend
uv sync
uv run pytest -q
uv run uvicorn app.main:app --reload --port 8000
```

После запуска проверить `http://localhost:8000/api/v1/health`, `http://localhost:8000/docs` и работу через Compose на чистой машине.
