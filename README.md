# ФСП.Карьера

Прототип платформы для подбора ИТ-специалистов по подтверждённым навыкам. Работодатель описывает потребность, получает кандидатов из подходящих категорий и сам отправляет приглашение с условиями и зарплатой. Категорию кандидата определяют опрос и тест; результаты ФСП могут дополнить профиль.

Проект делаем по [ТЗ ФСП](docs/00-tz-keypoints.md). Интерфейс и основные API запускаются вместе через Docker Compose.

## Что есть сейчас

| Компонент | Состояние |
|---|---|
| Backend | Есть модели данных и API авторизации, профилей, теста, подбора, приглашений и вакансий. Запуск с PostgreSQL проверен |
| ML-сервис | Предлагает навыки и их важность через Ollama и оценивает открытые ответы. Разбор резюме, оценка подбора и генерация вариантов пока заглушки. Если модель недоступна, обязательный открытый ответ ждёт ручной проверки |
| Frontend | React-приложение запускается через Compose; четыре теста навыков, результат, подбор и приглашение проверены в браузере |
| PostgreSQL и Redis | Запускаются через Compose; PostgreSQL проходит проверку готовности |
| Документация | Описаны API, техническая проверка теста и [сравнение сортировок](docs/09-ranking-review.md); качество на реальных людях ещё не проверено |

На запущенном Compose проверен путь от регистрации до принятия приглашения. Отдельный бенчмарк B-31 не уложился в заданный в нём порог времени ответа. Команды приведены в [инструкции по запуску](docs/03-api-and-run.md).

## Сценарий MVP

1. Кандидат регистрируется по email, заполняет профиль, выбирает специализацию и предполагаемый грейд.
2. Кандидат выбирает специализацию, язык базового теста и грейд. Сейчас для Backend доступен Python: четыре теста навыков по десять вопросов, развёрнутый ответ и задача с кодом. Набор открыт три дня. Предварительное правило: общий результат от 45 из 60 баллов и каждый из шести шагов от 50%. При низкой оценке открытого ответа итог ждёт ручной проверки. После завершения набора его можно один раз целиком пересдать с новым сроком в три дня; запасные открытые задачи ещё предстоит подготовить. После второй неудачи система предлагает грейд ниже; для Junior новый цикл доступен через неделю. Качество заданий и оценки нужно проверить на ответах людей. Старый общий тест из 12 заданий оставлен для совместимости и грейд больше не присваивает. Подробности — в [правилах тестирования](docs/02-testing-matching.md).
3. Работодатель описывает потребность и видит подходящие категории и кандидатов. Ранжирование опирается на результаты теста и подтверждённые достижения ФСП; причина рекомендации видна в карточке.
4. Работодатель отправляет приглашение с описанием предложения, способом связи и диапазоном зарплаты в рублях. Контакты кандидата раскрываются после принятия приглашения либо его самостоятельного отклика.

В ТЗ также предусмотрены профиль компании, поиск по банку кандидатов, статусы приглашений, настройки приватности и профиль кандидата без истории ФСП. Публикация вакансий и самостоятельные отклики желательны, но не обязательны для MVP. Короткие задания от работодателя тоже отнесены к дополнительным возможностям.

## Принятый технический подход

- Backend: Python 3.12, FastAPI, PostgreSQL 16, Redis.
- Frontend: React, Vite и Tailwind CSS; исходники добавлены.
- ML-сервис: отдельный Python API. В режиме описания задачи он обращается к Ollama и предлагает навыки с важностью 1–5. Явные грейд, зарплата и формат извлекаются отдельно; работодатель проверяет всё перед сохранением. Если Ollama недоступна, остаётся ручное заполнение. Новые Backend-наборы включают два открытых задания с модельной оценкой. При сбое модели грейд ждёт ручной проверки; подбор уже подтверждённых кандидатов работает без неё.
- Интеграция с ФСП: на демо используется локальный набор тестовых достижений. Привязка учётной записи через Keycloak/OIDC и получение достижений из реестра — разные будущие интеграции; API реестра организаторы не предоставили.

Подробности: [архитектура](docs/01-architecture.md), [тестирование и подбор](docs/02-testing-matching.md), [план валидации](docs/04-validation-dataset-model.md). Сравнение формулы с простой сортировкой — в [отчёте B-14](docs/09-ranking-review.md); отдельный учебный эксперимент с моделями — в [отчёте Романа](docs/15-ranking-model-experiment.md).

## Локальная проверка

Для backend используется `uv`:

```powershell
cd backend
uv sync
uv run pytest -q
uv run uvicorn app.main:app --reload --port 8000
```

После запуска проверить `http://localhost:8000/api/v1/health`, `http://localhost:8000/docs` и работу через Compose на чистой машине.
