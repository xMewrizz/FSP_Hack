# ФСП.Карьера — платформа обратного подбора ИТ-специалистов

> Хакатон ФСП 2026. Веб-сервис, где **работодатель сам находит кандидата** по верифицированным категориям (специализация + грейд), а не разбирает сотни откликов.

## 1. Суть в 30 секунд (что требует ТЗ)

**Обратная механика (ядро, 35% оценки):** соискатели распределяются по категориям на основе объективного профиля (опрос + тест + достижения ФСП), работодатель описывает потребность → получает ранжированную подборку с объяснением → отправляет приглашение конкретному человеку с зарплатой. Ориентир — модель LHH, но не копия.

**Категория = специализация + грейд** (пример: `Backend / Middle`). Внутри категории ранжирование: результаты тестов + вес достижений ФСП.

**Тестирование (25% оценки):** обязательный путь при регистрации: опрос → выбор предполагаемого грейда → тест на заявленный грейд. Требования:
- НЕ единый набор для всех (сольют ответы);
- НЕ чистая генерация LLM под каждого (не сопоставить сложность);
- Нужен свой гибрид: банк заданий по вариантам/параметризация + калибровка сложности (IRT-подобная логика). Детали — в `docs/02-testing-matching.md`.
- Грейд принудительно не понижается. Не сдал на заявленный → тест на уровень ниже. Сдал уверенно → повышение. Кулдаун смены грейда (мы берем **90 дней**).
- Плюс регулярные короткие задачи от работодателя для поддержки актуальности профиля (для MVP — желательно).

**ФСП ID:** своего API реестра нет. Делаем мок-слой + схему будущей интеграции через Keycloak (OIDC). Обязательна корректная обработка «истории ФСП нет».

**Правила видимости (обязательно):**
1. Зарплата `от–до` в рублях — везде: и в вакансии, и в приглашении. Кандидат видит условия до общения.
2. Контакты кандидата скрыты до `accepted` приглашения / самостоятельного отклика.
3. Статусы приглашений/откликов: `sent → viewed → accepted / rejected`. Видны обеим сторонам по своим записям.
4. Регистрация по email с подтверждением. Верификация компаний и модерация вакансий в MVP не нужны.

## 2. Стек (зафиксирован командой)

| Слой | Технология |
|---|---|
| Backend | Python 3.12 + FastAPI + SQLAlchemy 2.0 + Alembic + Pydantic v2 |
| DB | PostgreSQL 16 (основная), Redis (очереди/кэш/подборки) |
| Auth | JWT (access+refresh) + bcrypt, совместимость с Keycloak OIDC (под ФСП ID) |
| Frontend | React 18 + Vite 5 + Tailwind CSS + React Router + TanStack Query + Axios |
| ML/LLM | Python-сервис рядом с бэком: Qwen2.5 14B локально (Ollama / vLLM) для разбора резюме (PDF → поля), NLP-категоризации, генерации вариантов заданий, эмбеддинги для матчинга (E5 / BGE-M3) + скоринг |
| PDF | pypdf / pdfplumber (парсинг резюме) + reportlab/weasyprint (генерация стандартизированного PDF-профиля) |
| API docs | OpenAPI/Swagger из FastAPI (`/docs`) |
| Deploy | Docker + docker-compose (frontend / backend / db / redis / llm-service). Требование ТЗ: запуск одной командой |

Версии фиксируем в `backend/requirements.txt`, `frontend/package.json`, `docker-compose.yml`.

## 4. Роли MVP (что обязательно)

**Кандидат:** профиль/резюме (форма + PDF-парсинг + генерация PDF) → опрос → тест → категория/грейд + история → приглашения (принять/отклонить) → вакансии/отклики (доп., желательно) → настройки (приватность, согласие 152-ФЗ, привязка ФСП ID). Видит только свое.

**Работодатель:** профиль компании → описание потребности (стек/грейд/специализация) → подборка с обоснованием → банк с фильтрами → приглашение без обязательной привязки к вакансии + статусы → публикация вакансий (желательно). Не видит контактов до принятия.

**Поиск:** выдача только по категориям из тестов, не по самоописанию. Ранжирование + объяснимость («почему в подборке», «чего не хватает»), фильтры без потери подборки.

## 5. Быстрый старт (после scaffolding)

```bash
# 1. Клонировать и настроить env
cp .env.example .env

# 2. Поднять все
docker compose up --build

# Frontend: http://localhost:5173
# Backend Swagger: http://localhost:8000/docs
# LLM-service health: http://localhost:8001/health
```

Локально без докера:
```bash
# backend
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload
# frontend
cd frontend && npm i && npm run dev
# ml-service (веса Qwen тянутся отдельно, в репо не кладем)
ollama pull qwen2.5:14b && ollama serve
```

## 6. Команда (5 чел.) — предварительное распределение

- **ML-1 (PM + NLP/LLM):** PM, механика тестирования + валидация, ТЗ/доки/преза, промпты и калибровка Qwen.
- **ML-2 (NLP/LLM):** парсинг резюме PDF, эмбеддинги + матчинг/ранжирование, скоринг доверия.
- **ML-3 (DL/PINN, физика):** банк заданий + параметризация/варианты, метрики валидации (согласованность, дискриминативность), синтетические данные кандидатов/вакансий, аналитика качества.
- **Аналитик/дизайнер/тимлид:** UX обоих кабинетов (макеты уже есть), справочники специализаций/грейдов, демо-сценарий, преза, приемка.
- **Бэкенд (web3-контракты):** FastAPI + Postgres + Auth/JWT + Keycloak-ready, API для подбора/приглашений/вакансий, Docker, Swagger.
