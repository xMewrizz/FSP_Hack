# Как кандидат подтверждает грейд

Кандидат выбирает специализацию, язык программирования и грейд, который хочет подтвердить. Система показывает обязательные навыки выбранной специализации отдельными шагами. Список навыков одинаков для Junior, Middle и Senior; задания внутри каждого шага зависят от грейда. Сейчас есть два направления с базовым тестом на Python: Backend (Python, SQL, HTTP API, надёжность) и Data Science / ML (Python, Pandas, SQL, статистика, A/B-тестирование, ML). В каждом тесте навыка по десять самостоятельных вопросов.

Набор открыт три дня. При открытии система фиксирует задания, запасные варианты и правила подсчёта; обновление банка не меняет начатую попытку. Шаги можно проходить в разные дни. Результат каждого навыка показывается отдельно: например, «Python для Backend — 6 из 10 на уровне Middle». Эта оценка относится только к заданиям выбранного грейда.

Уровни различаются ожидаемым действием. Junior решает ограниченную задачу по заданным требованиям и замечает ошибки в своём решении. Middle самостоятельно планирует и доводит фичу или анализ до проверки результата, выбирает способ работы и объясняет компромиссы. Senior связывает решения нескольких частей системы, видит риски и зависимости, предлагает последовательность внедрения и критерии остановки. Senior может быть сильным индивидуальным специалистом без управления людьми. Ситуационные задачи проверяют эти действия, а не общительность или знание управленческих терминов.

**Грейд подтверждается после всех обязательных шагов.** В Junior-наборе к тестам навыков добавлены объяснение решения и задача с кодом. В Middle и Senior есть ещё сценарий самостоятельной работы: план фичи, разбор инцидента, решение при нескольких зависимостях или запуск модели. Он проверяет действия кандидата в конкретной ситуации, а не характер или должность руководителя. Каждый шаг даёт до 10 баллов; результаты тестов нормализуются к этой шкале. Нужно набрать не менее 75% общей суммы и не менее 50% на каждом шаге. Ровно 75% и ровно 50% проходят. Порог сравнивается без округления. Если открытый ответ ждёт ручной проверки, итогового решения пока нет.

Если в обязательном навыке меньше 50%, набор завершается сразу: подтвердить выбранный грейд уже нельзя. После неудачи можно **один раз пересдать весь набор** на том же грейде. Пересдача открывает отдельный набор на три дня; результаты двух наборов не смешиваются. Для открытых заданий назначаются другие практические ситуации и задачи с кодом. Вопросы с выбором ответа используют запасные формулировки; для части Data Science-вопросов они всё ещё проверяют то же правило в другом контексте, поэтому банк пересдачи требует дальнейшего расширения. После второй неудачи система предлагает полный набор на ступень ниже, но не понижает ранее подтверждённый грейд. Если не подтверждён Junior, новый цикл Junior доступен через неделю после пересдачи. Незавершённый набор истекает через три дня без присвоения грейда; отправленные вовремя ответы, ожидающие ручной проверки, сохраняют набор до решения проверяющего.

Для повышения кандидат проходит полный набор на одну ступень выше по тем же правилам. Начать повышение можно через 90 дней после последнего успешного присвоения грейда. Дополнительные навыки проверяются отдельно на уровне текущего подтверждённого грейда и не влияют на итог базового набора.

**Пороги предварительные.** Модельная оценка открытого ответа от 75% учитывается автоматически; меньший результат, сбой модели и её запрос на проверку требуют ручного решения. На подготовленном бенчмарке модель пропускала зачётные ответы, поэтому качество присвоения грейда нужно проверить на ответах людей разных уровней (B-32). Отсутствие модели теперь задерживает подтверждение нового грейда.
