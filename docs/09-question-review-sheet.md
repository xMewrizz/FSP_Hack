Лист пригодится, если появится человек, знакомый с Backend, или для будущих пробных прохождений. Заполнять его всей команде не нужно. Если тема незнакома, оставьте ответ пустым и отметьте это в замечании: угадывать не нужно. Решайте самостоятельно, не открывая исходный банк, ключи и объяснения. Если условие допускает несколько ответов или не хватает данных, запишите это в замечании. Не исправляйте вопрос до разбора ответов.

Лист содержит три версии каждой из 12 тем: всего 36 вопросов. Каждый вопрос предполагает один ответ A–D. После независимого решения сравните ответы с текущим ключом в коде и обсудите расхождения. Сам ключ нужно проверить по техническому источнику или воспроизводимому примеру. Время по каждому грейду и понятность условий запишите в конце.

## Версия 1

### Junior

**BE-JR-01.** Какое свойство ACID требует, чтобы зафиксированная транзакция сохранилась после сбоя процесса или перезапуска сервера при исправном хранилище?

- A. Atomicity (Атомарность)
- B. Consistency (Согласованность)
- C. Isolation (Изолированность)
- D. Durability (Долговечность)

**BE-JR-02.** Список Python содержит n элементов. Какова амортизированная сложность операции `items.append(value)`?

- A. O(1)
- B. O(log n)
- C. O(n)
- D. O(n log n)

**BE-JR-03.** Какой HTTP метод согласно стандарту RFC является идемпотентным и используется для полного замещения ресурса?

- A. POST
- B. PUT
- C. PATCH
- D. CONNECT

**BE-JR-04.** Что делает команда `git reset --soft HEAD~1`?

- A. Удаляет последний коммит и безвозвратно стирает все изменения в файлах
- B. Отменяет последний коммит, оставляя изменения в индексе (staged)
- C. Создает противоположный (revert) коммит
- D. Переключается на предыдущую ветку

- C. CREATE INDEX ON users (age)
- D. CREATE INDEX ON users (id, age)

- A. 1
- B. 100
- C. 0
- D. 50

- B. Транзакция зафиксирована

### Senior

**BE-SR-01.** Первый перевод с ключом идемпотентности откатился до сохранения ключа и денег. Клиент повторил запрос с теми же параметрами. Что должен сделать сервис?

**BE-SR-03.** Circuit breaker закрыт и переходит в Open после трёх ошибок подряд; успешный вызов обнуляет счётчик. Три вызова подряд завершились ошибкой. Каково состояние сразу после третьего?

- A. Closed
- B. Open
- C. Half-open
- D. Состояние нельзя определить

**BE-SR-04.** Заказ и событие записываются в одной транзакции БД: событие — в outbox. Транзакция откатилась до commit. Что сохранится?

- C. Ни заказ, ни запись outbox
