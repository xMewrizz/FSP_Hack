# Проверка оценивания открытых ответов (B-27)

Команда составила 37 ответов к четырём заданиям и заранее отметила, какие из 158 пунктов рубрик выполнены. Результаты сохранены в [JSON для модели 14B](../ml-service/benchmark_results_14b.json) и [JSON для резервного алгоритма](../ml-service/benchmark_results.json). Это проверка на подготовленных примерах, а не оценка качества на ответах реальных кандидатов.

| Метрика | Qwen 2.5 14B | Резервный алгоритм |
|---|---:|---:|
| Совпадение по отдельным критериям | 93,7% | 70,3% |
| Совпадение решения «зачёт/незачёт» | 81,1% (30 из 37) | 67,6% (25 из 37) |
| Ложные зачёты | 0 | 12 |
| Пропущенные зачёты | 7 | 0 |
| Средняя абсолютная ошибка балла | 0,096 | 0,321 |
| Медианное время оценки | 30,3 с | 0,3 мс |

В этот набор также вошли четыре примера с попыткой изменить инструкцию оценщика и четыре примера с синтаксическими ошибками Python. Модель и предварительные проверки обработали эти восемь примеров как ожидалось. По столь небольшому набору нельзя утверждать, что защита работает для всех вариантов таких ответов.

Главная выявленная ошибка модели — семь ответов, которым по разметке положен зачёт, получили незачёт. Перед использованием оценки для присвоения грейда нужно разобрать эти случаи и проверить модель на ответах людей. Это относится к проверке качества в B-32. При недоступности Ollama резервный алгоритм отправляет ответ на ручную проверку; его балл не присваивается автоматически.

Здесь приведён сохранённый прогон `qwen2.5:14b-instruct-q4_K_M`. В Compose по умолчанию настроена другая модель — `qwen3:8b`. Эти цифры нельзя переносить на неё без отдельного прогона.
