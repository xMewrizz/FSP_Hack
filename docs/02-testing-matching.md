# 02 — Тестирование + Матчинг + Валидация (черновик для доки к сдаче)

## Тестирование: гибрид «банк + параметризация + LLM-варианты»

Проблема ТЗ: один набор сливают; голая LLM-генерация не держит сложность.

Наше решение:
1. **Оси (6, как на радаре):** Язык / API / БД / Алгоритмы / Тесты / CI-CD.
2. **Банк:** на каждую ось × грейд (Junior/Middle/Senior) — 15–20 заданий-эталонов с эталонными ответами и рубрикой (0–7). Всего ~300 заданий на MVP-хватит 60–90 для Backend.
3. **Варианты:** каждое эталонное задание имеет 4–8 параметризованных вариантов (другие числа/таблицы/эндпоинты, та же сложность). Вариант выбирается сидом `hash(user_id + attempt)`.
4. **LLM (Qwen 14B):** только перефразировка условия и генерация дистракторов для MCQ + проверка открытых ответов по рубрике (LLM-as-judge с few-shot). Сложность якорена эталоном, а не придумана.
5. **Адаптив минимум:** старт со среднего, дальше ±1 шаг по IRT-подобному правилу; стоп после 12–15 заданий или SE < порога.
6. **Скоринг:** сумма по осям → радар 0–7 → пороги грейда + оценка доверия (согласованность ответов, время, расхождение с резюме).

Устойчивость к сливу: вариантов много + перефразировка + лимит попыток + кулдаун 90 дней + логирование сидов. Пересказ «ответа» не помогает — числа/кейсы другие.

## Категоризация
`Категория = специализация × подтвержденный грейд`. Подтвержденный грейд = min(заявленный, фактический по тесту) с правилом downshift/upshift из ТЗ.

## Матчинг
1. Фильтр по категории.
2. Скоринг: `0.5*skills_cosine(эмбеддинги потребности vs профиля) + 0.3*тест_по_осям(взвешенный важностями 1–5 из формы потребности) + 0.1*ФСП_вес + 0.1*актуальность`.
3. Объяснение: топ-3 совпавших оси + «зона роста» (мин. ось) + % совпадения (нормализация скора).
4. Сортировка по скору, фильтры не сбрасывают подборку (state в URL/query).

## Валидация (своя процедура, требуется ТЗ)
- Синтетика: 60 кандидатов (20 на грейд) + 5 вакансий. Разметка — ожидаемая категория от команды.
- Метрики: Precision@3/Recall топа, стабильность (retest agreement ≥80%), дискриминативность (AUC слабые/сильные), соответствие эксперту (Cohen kappa).
- Результаты кладем в `docs/validation-results.md` перед финалом + графики в презу.
