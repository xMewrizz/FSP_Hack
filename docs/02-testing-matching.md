# Тестирование, грейд и подбор

## Как кандидат подтверждает грейд

Кандидат выбирает специализацию, язык программирования базового теста и предполагаемый грейд. У каждой специализации есть постоянный список обязательных навыков. Для Junior, Middle и Senior список **один и тот же**; меняется сложность заданий. Тест не подбирается под конкретную вакансию. Сейчас для Backend доступен только Python; Python для Backend и Python для Data Science будут разными проверками.

В кабинете обязательные навыки показаны как шаги. Кандидат проходит их отдельно и может вернуться к следующему навыку позже. Новый Backend-набор также содержит развёрнутый ответ и задачу с кодом, закреплённые при старте. Набор открыт три дня. Тестовые вопросы и варианты фиксируются при открытии; изменения банка не влияют на начатый набор. Пока все шесть шагов выбранного грейда не завершены, итогового решения о грейде нет. Ответы, ожидающие ручной проверки, задерживают решение.

Результаты складываются по баллам: четыре теста навыков дают до 10 баллов каждый после нормализации, два открытых задания — ещё по 10. **Предварительное правило** для присвоения грейда: не менее 45 из 60 баллов **и** не менее 50% на каждом из шести шагов. Ровно 75% и ровно 50% достаточно. Порог сравнивается с точным значением, без округления отображаемого процента. Его качество проверим на реальных ответах в B-32.

В профиле показываем каждый результат отдельно, например: «Python для Backend — 6 из 10 на уровне Middle». Это баллы за задания данного уровня, а не утверждение об абсолютном владении Python. Пока навык не проверен, вместо числа пишем «не пройден». Дополнительные навыки проверяются отдельно на текущем подтверждённом грейде; они видны в профиле, но **не входят** в обязательную сумму и не присваивают грейд. Другой язык программирования можно проверить дополнительно, когда для него появится банк.

Если обязательный навык набрал меньше 50%, набор завершается сразу: подтвердить этот грейд уже невозможно. Кандидат видит результат навыка и может один раз пересдать **весь набор** на том же грейде; отдельный навык пересдать нельзя. Пересдача открывается отдельным набором на три дня с заранее сохранёнными запасными вариантами заданий. Результаты двух наборов не смешиваются. После второй неудачи система предлагает полный набор на грейд ниже, если он есть, но не понижает подтверждённый грейд автоматически. После двух неудачных наборов Junior новый цикл Junior доступен через неделю после завершения пересдачи. Для повышения на одну ступень кандидат запускает полный набор следующего грейда. Перескочить через ступень нельзя. После Senior тест на Lead не предлагаем. Смену подтверждённого грейда ограничиваем 90 днями от последнего успешного присвоения; неудача и пересдача того же грейда срок не обновляют.

### Наборы навыков

Для первого рабочего направления Backend выбраны четыре обязательных блока: Python для Backend, SQL и работа с данными, HTTP API, надёжность сервиса. Для каждого грейда подготовлено по десять самостоятельных вопросов на навык — 40 вопросов на полный набор. У каждого вопроса три варианта для разных попыток; они не прибавляются к числу самостоятельных вопросов. Техническую корректность новых вопросов и соответствие сложности грейду нужно проверить независимо.

Для Data Science выбраны шесть отдельных обязательных навыков: Python для анализа данных, Pandas, SQL, вероятность и статистика, A/B-тестирование, машинное обучение. Для каждого подготовлено по десять вопросов на Junior, Middle и Senior. Это пока банк для проверки: прохождение Data Science и присвоение грейда в кабинете ещё не открыты. Формулировки и разделение уровней требуют предметной проверки; состав банка описан [отдельно](17-data-science-question-bank.md). Spark, Docker, CI/CD, Git и FastAPI могут быть дополнительными навыками, если не включены в обязательный набор конкретной специализации.

[Рабочее предложение для всех девяти специализаций](14-specialization-skills.md) составлено по открытым рамкам компетенций и документации платформ. Оно не открывает тесты для этих направлений без согласованного банка и проверки заданий.

## Что уже работает и что нужно переделать

Сейчас подготовлены по десять самостоятельных вопросов для каждой пары «Backend-навык × грейд» и три варианта каждого вопроса. API хранит фиксированный набор, отдельную попытку по каждому навыку и связь между первым полным набором и его единственной пересдачей. Два открытых задания тоже привязаны к набору; кабинет показывает их и сохранённую оценку. Грейд меняется только после всех обязательных шагов. Дополнительно доступен Git на уровне Junior после подтверждения Junior; порог «подтверждён» для дополнительных тестов ещё не задан, поэтому показывается только результат. Технические ключи новых заданий и пригодность уровня Senior требуют независимой проверки.

Старый маршрут `/testing/start` сохранён для совместимости: он выдаёт 12 заданий одной сессией и показывает результат по прежнему порогу 9 из 12, но **больше не присваивает грейд**. Для нового сценария используется `/testing/roadmap`. Состав банка и оставшаяся работа описаны в [банке заданий](07-question-bank.md). API и полный путь с PostgreSQL проверены; браузерный сценарий ещё нужно пройти вручную.

Открытые задания теперь обязательны в новых Backend-наборах. Оценка ниже 75% по отдельному ответу не отклоняет кандидата автоматически: такой ответ ждёт ручной проверки. Качество модели на реальных ответах ещё не подтверждено. Запасные открытые задачи для пересдачи и хранение эталонов вне публичного кода остаются работой B-27.

## Подбор

Работодатель выбирает один из двух способов заполнения потребности. В ручном режиме он сам задаёт навыки и важность 1–5. Во втором режиме описывает задачи обычным текстом: LLM предлагает навыки и выставляет их важность, даже если технологии не перечислены явно. Специализация может быть предложена моделью; грейд, зарплата и формат берутся только из явно указанного в тексте. Название роли и город работодатель заполняет сам. Предложения переносятся в форму только по его нажатию, после чего он может изменить навыки и ползунки. Если модель недоступна, ручная форма работает без неё. Качество весов на реальных описаниях ещё не проверено.

Работодатель задаёт специализацию, грейд, стек, важность навыков и диапазон зарплаты. В подбор и банк работодателя попадают только кандидаты с подтверждённым грейдом нужной специализации, разрешившие публикацию профиля. Заявленный грейд нужен кандидату для выбора теста и не служит основанием для выдачи. Достижения ФСП могут влиять на порядок внутри категории, но не присваивают грейд; демонстрационные записи нельзя выдавать за проверку личности. Резюме дополняет профиль. Карточка подбора объясняет, какие навыки указаны в профиле, а какие нет. Для навыков потребности, по которым есть отдельный завершённый тест на подтверждённом грейде, показываем результат теста. При трёх и более запрошенных навыках строим многоугольник: одна вершина на навык, внешний контур — 100% баллов за тест; при одном или двух показываем список результатов. Если результата нет, это отмечено отдельно и не считается нулевым владением. Результат теста по широкой теме не подставляется за конкретную технологию: например, тест по HTTP API не оценивает FastAPI. Балл подбора учитывает и навыки из профиля, и результаты отдельных тестов по запрошенным навыкам; отсутствие результата не даёт баллов за проверку, но не означает отсутствие знаний. График показывает те же результаты, которые использует расчёт. Процент совместимости показываем лишь после проверки шкалы и калибровки. План проверки качества описан в [плане валидации](04-validation-dataset-model.md).
