# Тестирование, грейд и подбор

## Как кандидат подтверждает грейд

Кандидат выбирает специализацию, язык программирования базового теста и предполагаемый грейд. У каждой специализации есть постоянный список обязательных навыков. Для Junior, Middle и Senior список **один и тот же**; меняется сложность заданий. Тест не подбирается под конкретную вакансию. Сейчас для Backend доступен только Python; Python для Backend и Python для Data Science будут разными проверками.

В кабинете обязательные навыки показаны как шаги. Кандидат проходит их отдельно и может вернуться к следующему навыку позже. Набор открыт три дня. Задания и варианты фиксируются при открытии; изменения банка не влияют на начатый набор. После истечения срока грейд по нему не присваивается. Пока все обязательные шаги выбранного грейда не завершены, итогового решения о грейде нет.

Результаты складываются по баллам: сумма полученных баллов делится на сумму возможных по всем обязательным навыкам. **Предварительное правило** для присвоения грейда: общий результат не ниже 75% **и** результат каждого обязательного навыка не ниже 50%. Ровно 75% и ровно 50% достаточно. Порог сравнивается с точным значением, без округления отображаемого процента. Его качество проверим на реальных ответах в B-32.

В профиле показываем каждый результат отдельно, например: «Python для Backend — 6 из 10 на уровне Middle». Это баллы за задания данного уровня, а не утверждение об абсолютном владении Python. Пока навык не проверен, вместо числа пишем «не пройден». Дополнительные навыки проверяются отдельно на текущем подтверждённом грейде; они видны в профиле, но **не входят** в обязательную сумму и не присваивают грейд. Другой язык программирования можно проверить дополнительно, когда для него появится банк.

Если навык набрал меньше 50%, кандидат видит это сразу, но завершает остальные шаги; отдельный навык пересдать нельзя. После полного набора доступна одна пересдача **всех обязательных навыков** на том же грейде. Она открывается отдельным набором на три дня с заранее сохранёнными запасными вариантами заданий. Результаты двух наборов не смешиваются. После второй неудачи система предлагает полный набор на грейд ниже, если он есть, но не понижает подтверждённый грейд автоматически. После двух неудачных наборов Junior новый цикл Junior доступен через неделю после завершения пересдачи. Для повышения на одну ступень кандидат запускает полный набор следующего грейда. Перескочить через ступень нельзя. После Senior тест на Lead не предлагаем. Смену подтверждённого грейда ограничиваем 90 днями от последнего успешного присвоения; неудача и пересдача того же грейда срок не обновляют.

### Наборы навыков

Для первого рабочего направления Backend выбраны четыре обязательных блока: Python для Backend, SQL и работа с данными, HTTP API, надёжность сервиса. Для каждого грейда подготовлено по десять самостоятельных вопросов на навык — 40 вопросов на полный набор. У каждого вопроса три варианта для разных попыток; они не прибавляются к числу самостоятельных вопросов. Техническую корректность новых вопросов и соответствие сложности грейду нужно проверить независимо.

Для Data Science состав набора нужно согласовать до подготовки заданий. Рабочий вариант: Python, Pandas и подготовка данных, SQL, вероятность и статистика, A/B-тесты, основы машинного обучения. Важно проверять применение методов, а не узнавание названий. Spark, Docker, CI/CD, Git и FastAPI могут быть дополнительными навыками, если не включены в обязательный набор конкретной специализации. Список дополнительных навыков не ограничен этим примером.

[Рабочее предложение для всех девяти специализаций](14-specialization-skills.md) составлено по открытым рамкам компетенций и документации платформ. Оно не открывает тесты для этих направлений без согласованного банка и проверки заданий.

## Что уже работает и что нужно переделать

Сейчас подготовлены по десять самостоятельных вопросов для каждой пары «Backend-навык × грейд» и три варианта каждого вопроса. API хранит фиксированный набор, отдельную попытку по каждому навыку и связь между первым полным набором и его единственной пересдачей. Экран показывает прогресс и результат. Грейд меняется только после всех обязательных шагов. Дополнительно доступен Git на уровне Junior после подтверждения Junior; порог «подтверждён» для дополнительных тестов ещё не задан, поэтому показывается только результат. Технические ключи новых заданий и пригодность уровня Senior требуют независимой проверки.

Старый маршрут `/testing/start` сохранён для совместимости: он выдаёт 12 заданий одной сессией и показывает результат по прежнему порогу 9 из 12, но **больше не присваивает грейд**. Для нового сценария используется `/testing/roadmap`. Состав банка и оставшаяся работа описаны в [банке заданий](07-question-bank.md). API и полный путь с PostgreSQL проверены; браузерный сценарий ещё нужно пройти вручную.

Задания с развёрнутым ответом и проверкой LLM остаются расширением P1. Для них нужны критерии оценки и проверка качества модели на заранее оценённых ответах; спорные ответы отправляем на ручной разбор. Пока таких заданий в работающем тесте нет.

## Подбор

Работодатель задаёт специализацию, грейд, стек, важность навыков и диапазон зарплаты. В подбор и банк работодателя попадают только кандидаты с подтверждённым грейдом нужной специализации, разрешившие публикацию профиля. Заявленный грейд нужен кандидату для выбора теста и не служит основанием для выдачи. Достижения ФСП могут влиять на порядок внутри категории, но не присваивают грейд; демонстрационные записи нельзя выдавать за проверку личности. Резюме дополняет профиль. Карточка подбора должна объяснять конкретные совпадения и пробелы; процент совпадения показываем лишь после проверки шкалы и калибровки. План проверки качества описан в [плане валидации](04-validation-dataset-model.md).
