# Развёрнутые задания и проверка ответов (B-27)

В базовых наборах Backend и Data Science / ML есть задания с текстовым ответом и кодом. На Junior их два, на Middle и Senior — три, включая рабочую ситуацию. Для пересдачи используются другие задания. Коды фиксируются при открытии набора и не меняются во время прохождения.

Каждый ответ даёт до 10 баллов. Для подтверждения грейда нужны все обязательные навыки и развёрнутые задания: общий результат не ниже 75%, каждый шаг — не ниже 50%. Низкая оценка одного ответа входит в общий расчёт и сама по себе не отправляет кандидата на ручную проверку. Начатые до введения открытых заданий наборы сохраняют прежние правила.

## Как проходит проверка

1. Кандидат отправляет ответ. Backend проверяет, что задание принадлежит его открытому набору, и сохраняет текст в PostgreSQL со статусом `queued`.
2. Фоновый обработчик передаёт условие, критерии, эталон и ответ в ML-сервис. Кандидат может решать следующие задания, пока идёт оценивание.
3. Итоговая оценка строится из выполненных критериев. Она сохраняется вместе с объяснением; после оценки всех шагов backend рассчитывает грейд. Предварительный балл резервного алгоритма для этого не используется.
4. Если модель недоступна, текст ответа остаётся сохранённым со статусом `failed`. Кандидат может повторить автоматическую проверку того же ответа после восстановления сервиса. Переписывать ответ не нужно.

Если все шаги отправлены в пределах трёх дней, набор остаётся в ожидании итоговой оценки и не закрывается только из-за задержки модели. Новые ответы после окончания срока набора не принимаются.

Попытки подменить инструкции оценщику помечаются отдельно. В backend есть API для разбора таких ответов администратором, однако регулярный процесс проверки и ответственный за него пока не назначены. Нельзя обещать кандидату срок ручного решения.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/testing/open-questions?specialization=...&grade=...` | Условия и критерии без эталонных ответов |
| `POST` | `/api/v1/testing/open-questions/{code}/queue` | Сохранить ответ и поставить его на оценивание |
| `GET` | `/api/v1/testing/open-submissions` | Свои ответы, статусы, оценки и объяснения |
| `POST` | `/api/v1/testing/open-submissions/{id}/queue-retry` | Повторить проверку сохранённого ответа после сбоя |
| `GET` | `/api/v1/testing/open-submissions/pending-review` | Очередь спорных ответов; доступна только администратору |
| `POST` | `/api/v1/testing/open-submissions/{id}/review` | Решение администратора по спорному ответу |

Прямой маршрут `/submit` сохранён для совместимости и тестов. Интерфейс кандидата использует очередь, чтобы не удерживать страницу во время ответа модели.

## Что ещё не проверено

Сохранённый [прогон на подготовленных ответах](20-b27-benchmark-validation-report.md) относится к локальной Qwen 2.5 14B. Его метрики нельзя переносить на нынешнюю модель OpenRouter или на ответы реальных кандидатов. Нужны независимые ответы людей и разбор ошибок оценки.

Эталонные решения не выдаются через кандидатский API, но они уже присутствуют в исходниках и истории публичного репозитория. Удаление строк из текущей версии не скроет опубликованные ответы. Перед использованием теста для реального подтверждения навыков понадобится новый закрытый банк или серверный источник заданий с контролем доступа.
