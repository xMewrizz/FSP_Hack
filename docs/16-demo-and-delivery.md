# Показ проекта и материалы к сдаче

## Короткое описание для промежуточной заявки

ФСП.Карьера помогает работодателю найти кандидата по подтверждённой специализации и грейду и самому отправить приглашение. Кандидат сначала выбирает направление и предполагаемый грейд, затем проходит одинаковые для своего направления обязательные блоки навыков. Сейчас рабочий базовый набор есть для Backend на Python: четыре навыка по десять вопросов на Junior, Middle и Senior. Темы сохраняются между грейдами, сложность заданий меняется. Вопросы и запасные варианты фиксируются на время попытки, а для пересдачи используется другой вариант. Так результаты внутри одного грейда можно сравнивать, не выдавая всем дословно один и тот же тест. Качество формулировок и различение грейдов ещё проверяются.

Подбор допускает только опубликованные профили с подтверждённой нужной категорией; заявленный грейд сам по себе доступа не даёт. Внутри категории кандидаты ранжируются по результатам навыков, требованиям работодателя и достижениям ФСП. Карточка показывает причины рекомендации. На небольшом синтетическом наборе мы сравнили этот порядок с простой сортировкой по совпадению навыков; цифры и ограничения приведены ниже. Контакты раскрываются работодателю после принятия приглашения кандидатом.

## Что можно показать сейчас

Основной путь после изменения B-27: регистрация кандидата, профиль, четыре теста навыков Backend, два открытых задания, результат, подбор работодателя, приглашение и ответ кандидата. Для Backend доступен язык Python и грейды Junior, Middle, Senior. Каждый новый набор содержит четыре навыка по десять вопросов и два открытых задания. Набор открыт три дня; пороги 75% в целом и 50% по каждому шагу предварительные. Для подтверждения нового грейда нужна доступная модель или ручная проверка открытых ответов. Путь до грейда с ручной проверкой пройден через API на изолированном PostgreSQL; весь путь в браузере после изменения ещё нужно пройти.

На 9 октября 2026 года запуск проверен на отдельном Compose-проекте с пустой базой. Скрипт `backend/smoke_compose.py` прошёл путь от регистрации двух учётных записей до принятия приглашения. Это проверка работы системы, а не оценка качества заданий людьми.

## Самостоятельный проход

1. Откройте интерфейс по адресу, указанному в материалах сдачи. Для локального запуска это `http://localhost:5173`; команды приведены в [инструкции](03-api-and-run.md).
2. Зарегистрируйте кандидата. Код подтверждения в локальном демо показывается на экране. Заполните профиль, выберите Backend, Python и предполагаемый грейд Junior, Middle или Senior. Для других специализаций готового базового теста пока нет.
3. В разделе «Тестирование» откройте набор, пройдите четыре теста навыков и отправьте два развёрнутых ответа. Задания фиксируются при создании набора. Итог по грейду появится после всех шести шагов и, если требуется, ручной проверки. В профиле можно посмотреть баллы по навыкам и историю.
4. Зарегистрируйте работодателя с другим email, заполните компанию и создайте потребность по Backend и подтверждённому грейду кандидата. Откройте подборку, изучите объяснение и отправьте приглашение с условиями и зарплатой.
5. Вернитесь в аккаунт кандидата, примите приглашение. Работодатель увидит статус и контакты после принятия.

Прохождение набора из 42 заданий занимает столько времени, сколько потребуется человеку; обещать короткое прохождение нельзя. Для быстрого обзора интерфейса можно использовать демонстрационные данные, но они не заменяют самостоятельное прохождение теста. При отсутствии LLM открытые ответы ждут ручной проверки, и грейд пока не присваивается. Достижения ФСП в демо берутся из локальных тестовых данных.

## Цифры и ограничения для презентации

- Базовый Backend-тест: четыре обязательных навыка, по десять заданий на навык, три грейда. Банк и ключи проходят технические проверки; сложность заданий на ответах людей пока не оценивалась (B-32).
- В техническом сравнении подбора формула B-14 поставила кандидата с наивысшей меткой первым в трёх из трёх синтетических потребностей. Простая сортировка поставила его вторым. `nDCG@4`: 1,000 против 0,797; `P@3`: 0,333 у обоих подходов. Это небольшой синтетический набор с предварительными метками, а не доказательство качества на реальных работодателях. Методика и таблица — в [сравнении](09-ranking-review.md).
- Качество порогов, заданий и подбора на реальных людях пока не проверено; эта работа вынесена в B-32.

## Промежуточная сдача

Для промежуточной сдачи подготовлены короткое описание подхода к тесту и подбору с обоснованием и сценарий демонстрации. Описание и технические подробности есть в репозитории; отдельный DOC/PDF на этом этапе не требуется.

## Если пройдём отбор

К финалу понадобятся ссылка на презентацию, ссылка на развёрнутый прототип и ссылка на сопроводительную документацию в DOC или PDF. Если развернуть сервис не получится, вместо ссылки на него приложить видео и инструкцию локального запуска. Адрес стенда или видео в репозитории пока не указан; локальный `localhost` доступен только на компьютере, где запущен проект. Перед передачей внешней ссылки открыть её без авторизации с другого устройства и пройти путь из этого документа.
