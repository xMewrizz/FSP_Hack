# Архитектура MVP

Здесь описано, как работают части сервиса. В репозитории есть frontend, API, модели данных, миграции и тесты. Все компоненты запускались через Compose; ML-сервис может запросить Ollama для предложения навыков по описанию потребности, остальные маршруты пока заглушки.

## Пользовательский путь

```text
Кандидат: email → профиль → опрос → заявленный грейд → тест → категория → приглашение
Работодатель: email → компания → потребность → категории и кандидаты → приглашение → ответ
```

Категория складывается из специализации и подтверждённого грейда. Кандидат без результатов ФСП остаётся доступен для подбора. Историю тестов и изменения грейда следует хранить отдельно от текущей категории.

## Компоненты

| Компонент | Назначение | Состояние |
|---|---|---|
| Frontend | Два кабинета, формы, подборка, приглашения | Запускается через Compose; основной путь и разбор потребности проверены в браузере |
| Backend | Авторизация, профили, тесты, подбор, приглашения, правила доступа | Запускается с PostgreSQL; основной сценарий проверен через API |
| PostgreSQL | Пользователи, профили, задания, попытки, потребности, приглашения | Контейнер запускается и проходит проверку готовности |
| Redis | Кэш подборок и временное состояние попыток при необходимости | Контейнер описан, не используется |
| ML-сервис | Предложение навыков и весов по тексту через Ollama; извлечение явно названных полей | Контракт проверен с имитацией ответа модели, реальный прогон с Qwen ещё нужен; три других маршрута — заглушки |

Frontend обращается к backend. Backend проверяет права доступа и работает с базой. ML-сервис вызывается только для отдельных операций и получает лишь нужные для них данные.

Основной тест и подбор должны работать, даже если LLM недоступна. Задания с развёрнутым ответом и проверкой моделью относятся к P1; при сбое модели такой ответ ждёт ручного разбора, а не получает автоматический балл. На стенде жюри нет GPU, поэтому запуск тяжёлой локальной модели не должен быть обязательным. Если используем внешний API, сначала решаем, какие данные ему можно отправлять. В документации укажем модель, место её запуска и то, что происходит при сбое.

## Данные и границы доступа

Основные сущности: пользователь и роль, профиль кандидата, компания, специализация, задание и вариант, попытка теста, подтверждённая категория, потребность работодателя, приглашение, вакансия и отклик (последние два — дополнительный сценарий), связь с ФСП ID и достижения. На уровне backend кандидат читает только свои приглашения и отклики. Работодатель получает публичную часть профиля; контакты возвращаются только после принятого приглашения от этого работодателя либо отклика кандидата на его вакансию. Фильтр в интерфейсе не заменяет проверку доступа в API.

Согласия на обработку и публикацию профиля хранятся раздельно с датой и версией текста. До публикации профиля в поиске проверяется соответствующее согласие. Пароли хранятся в виде стойких хешей, токены имеют ограниченный срок жизни. Перед сдачей нужны проверка ролевого доступа и сценарии отзыва согласия.

## Связь с ФСП

В демо backend обращается к локальному набору тестовых достижений по введённому ФСП ID. Ответ может быть пустым; это не ошибка и не основание исключать кандидата. В интерфейсе нельзя выдавать тестовые записи за сведения официального реестра.

Будущая интеграция состоит из двух независимых частей: вход или привязка учётной записи через Keycloak/OIDC и получение достижений из реестра ФСП. Наличие OIDC само по себе не даёт данных реестра. После публикации API ФСП понадобится отдельный адаптер данных и проверка происхождения достижений.

## Производительность и сбои

В выдачу работодателя попадают кандидаты с подтверждённой категорией, разрешившие публикацию профиля. Заявленный грейд нужен для выбора теста и не даёт права попасть в подбор или банк работодателя. Внутри подходящей категории кандидатов сортируем по соответствию потребности. Поиск должен открываться постранично и не тормозить при росте базы. Кэш добавим после замеров и будем обновлять при изменении профиля, теста или потребности. Если LLM недоступна, используем готовые задания и обычный расчёт совпадения. Время ответа пока не измеряли.
