# 01 — Архитектура (MVP)

## Функциональная схема

```
[Кандидат] → Регистрация(email) → Профиль/Резюме(PDF-парсинг) → Опрос → Тест → Категория → Приглашения/Отклики
[Работодатель] → Профиль компании → Потребность → Подборка/Банк → Приглашение(с ЗП) → Статусы → Вакансии*
ФСП-мок → обогащение профиля (достижения, вес в ранжировании)
```

## Компоненты

- **frontend (React+Vite+Tailwind):** SPA, две ролевые зоны, общий дизайн из макетов. Ходит только в `backend` по REST.
- **backend (FastAPI, порт 8000):** Auth, Users, Profiles, Testing, Matching, Invitations, Vacancies, FSP-mock, PDF-profile. Реляционная логика в Postgres, очереди/кэш в Redis.
- **ml-service (Python, порт 8001):** три ручки: `/parse-resume`, `/score-match`, `/task-variant`. Внутри — Qwen2.5:14B (Ollama/vLLM) + эмбеддинги (BGE-M3/E5) + rule-based фолбэк. Backend вызывает его асинхронно, фронт — никогда напрямую.
- **db (Postgres 16):** users, companies, candidate_profiles, tests, tasks, categories, needs, matches, invitations, vacancies, fsp_links.
- **redis:** сессии/rate-limit тестов, кэш подборок, очередь микро-задач.

Почему так: ТЗ требует явного разделения Frontend/Backend/Хранение; микросервис для ML — отдельно, чтобы локальный Qwen у сокомандника не ронял основной бэк и чтобы был фолбэк без LLM.

## Интеграция ФСП (заглушка сейчас → Keycloak потом)

```
Кандидат вводит ФСП ID → backend дергает fsp-mock (наш JSON) → достижения + вес → показываем бейджем (как на скрине «Призёр ИТМО 2024»)
Позже: fsp-mock заменяется OIDC Keycloak → тот же интерфейс, другой провайдер.
Если истории нет → профиль все равно работает, бейджа нет, скоринг без бонуса.
```

Поля мока (наше решение, ТЗ отдало на откуп): `fsp_id, nickname, events[{name, year, place, type}], rating, verified: bool`.

## Безопасность (152-ФЗ минимум)
Согласие на обработку/публикацию (чекбокс + хранение), роли `candidate/employer`, скрытие контактов на уровне сериализаторов (не только на фронте), bcrypt + JWT, подтверждение email, логирование доступов к контактам.

## Производительность MVP
Подборка — предрасчет скоринга + кэш в Redis, пагинация банка, индексы по (specialization, grade, stack).
