# Бэклог проекта

Рабочий план на начало разработки. Здесь перечислены задачи и проверяемый результат каждой. `P0` — нужен для сквозного сценария и обязательных требований ТЗ; `P1` — улучшает MVP; `P2` — дополнительная возможность. Зависимость означает, что для завершения задачи нужен результат предыдущей, но проектирование и макеты можно делать параллельно.

Сейчас частично готов только технический каркас B-00: есть Compose, два FastAPI-приложения и Dockerfile frontend. Исходников интерфейса, схем БД и рабочих пользовательских сценариев ещё нет. Остальные задачи не отмечаются выполненными до проверки критериев ниже.

## Очерёдность

Сначала доводим B-00 до работающего запуска. Параллельно можно готовить справочники B-05, банк B-07, макеты и тестовые данные B-24. Затем идут два потока: профиль кандидата B-01 → B-02 → B-08 → B-09 → B-10 и профиль работодателя B-01 → B-12 → B-13. Подбор B-14 соединяет результаты этих потоков и данные ФСП B-20. После него завершаем поиск B-17 и приглашения B-15 → B-16. Валидация B-23 использует готовые тест и подбор; сдача B-29 опирается на проверенный сценарий и фактические результаты.

Если сроки сжимаются, сначала переносим задачи P2, затем P1. Не заменяем обязательный сценарий демонстрационными числами или заглушками, которые выглядят как работающий подбор.
