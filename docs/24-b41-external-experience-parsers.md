# B-41: Внешние парсеры верификации опыта и детекция накрутки стажа («возможно крутит опыт»)

**Исполнитель:** Султан (Backend Lead / Платформенная архитектура)  
**Приоритет:** P1
**Связанные задачи:** B-23 (Проверка сведений из резюме), B-24 (Оценка доверия и True Score), B-05 (Профиль кандидата и согласия 152-ФЗ)  
**Статус:** Частично

Парсеры сейчас разбирают переданные им HTML и JSON на тестовых примерах. Публичный API не загружает страницы площадок, не подтверждает принадлежность внешнего профиля кандидату и не сохраняет проверенную версию со ссылкой и датой проверки. Поэтому работающий эндпоинт возвращает «недостаточно данных», пока такая интеграция не появится. Ранее ссылка, вставленная кандидатом в резюме, порождала вымышленные сведения о стаже и могла дать ложный подозрительный статус; эта подстановка удалена.

---

## 1. Контекст и бизнес-цель

В рамках платформы обратного подбора ФСП ключевой ценностью является защита работодателей от недобросовестных кандидатов, искусственно завышающих профессиональный стаж и квалификацию («накрутка опыта»).

Цель задачи **B-41**:
1. Разработать модули сбора и парсинга данных с трёх внешних площадок: **Хабр Карьера**, **Careerist** и **Профи.ру**.
2. Учесть юридические и технические ограничения каждой площадки (правила API Хабра, ограничения каталога Careerist, специфика фриланса Профи.ру).
3. Реализовать движок сопоставления заявленного опыта с внешней историей и детекцию накрутки стажа со статусом **«возможно крутит опыт»**.
4. **Обеспечить абсолютную конфиденциальность кандидата (Privacy by Design):** кандидат никогда не видит, что система присвоила ему подозрительный статус. Этот статус и детали аудита доступны исключительно авторизованным работодателям и рекрутерам.
5. Соблюсти требования 152-ФЗ: автоматический сбор открытых данных (OSINT) запускается только при наличии явного согласия кандидата (`agreed_osint = true`).

## 2. Анализ внешних площадок и реализация парсеров

### 2.1. Хабр Карьера (`career.habr.com`)

- **Ценность:** Самый достоверный источник сведений об IT-опыте в РФ. Профили содержат наименования компаний, точные периоды работы (месяц, год), должности и подтверждённый стек.
- **Ограничения:**
  - Полнотекстовый поиск по всей базе соискателей в API ограничен политикой платформы.
  - Использование официального API регламентируется [Правилами API Хабр Карьеры](https://career.habr.com/info/legal/api_rules).
  - Для работы с API требуются:
    1. Регистрация клиентского приложения (`client_id`, `client_secret`).
    2. Ручная модерация и активация приложения администрацией Хабра.
- **Реализация (`HabrCareerParser`):**
  - Метод `check_api_status`: проверяет наличие регистрации приложения и статус активации администрацией Хабра.
  - Метод `parse_api_response`: разбирает структурированный JSON-ответ официального API (поля `first_name`, `last_name`, `title`, `qualification`, `companies`, `positions`, `experience_dates`, `duration_months`, `skills`).
  - Метод `parse_html`: парсит открытые страницы профилей (`https://career.habr.com/<username>`), извлекая карточки мест работы, даты (включая открытые концы «сентябрь 2021 — настоящее время») и перечень подтверждённых навыков.

### 2.2. Careerist (`careerist.ru`)

- **Ценность:** На [странице резюме программистов](https://careerist.ru/cvs-programmist/) публикуются структурированные резюме со сведениями о совокупном стаже, последнем работодателе и стеке.
- **Ограничения и условия использования:**
  - *Критическое замечание:* **Отсутствие капчи само по себе не гарантирует доступ к полным резюме и не отменяет условий использования (Terms of Service).**
  - Платформа не обходит технические барьеры и не нарушает пользовательское соглашение.
  - В открытом доступе каталог отдаёт сниппеты и метаданные стажа (превью). Доступ к полным контактным данным и развёрнутому описанию проектов требует авторизованного аккаунта работодателя.
- **Реализация (`CareeristParser`):**
  - Метод `check_access_and_terms`: проверяет уровень доступа (`preview_snippets` для гостя vs `authorized_employer_full` для авторизованного работодателя), гарантирует отказ от обхода капчи.
  - Метод `parse_cv_catalog`: извлекает карточки программистов из открытого каталога (желаемая должность, совокупный стаж в годах и месяцах, последняя компания, город).
  - Метод `parse_cv_detail`: разбирает детальную страницу резюме или модальное превью (история занятости, должности, стек).

### 2.3. Профи.ру (`profi.ru`)

- **Ценность:** [Профили IT-специалистов](https://profi.ru/it_freelance/data-scientist/) (например, Data Scientist, Python-разработчики) дополняют общую картину практических навыков.
- **Специфика площадки:**
  - Профиль на Профи.ру — это анкета специалиста/фрилансера (услуги, репетиторство, частные заказы, рейтинг, отзывы клиентов), а не классическое резюме с трудовой книжкой.
- **Ключевое правило платформы:**
  > **Само наличие подработки или репетиторства на Профи.ру НЕ означает завышения опыта («не крутит опыт»).**
  > Частная практика является законной деятельностью и свидетельствует о практической активности кандидата. Она учитывается как дополнительное подтверждение навыков, но отсутствие там записей о трудовом договоре ни в коем случае не пенализирует соискателя.
- **Реализация (`ProfiRuParser`):**
  - Метод `check_profi_policy`: возвращает официальную гарантию неприменения санкций за репетиторство и подработку.
  - Метод `parse_specialist_catalog`: извлекает специалистов, рейтинг, число выполненных заказов и стаж частной практики.
  - Метод `parse_profile`: парсит перечень услуг, средний балл отзывов и годы практики с выставлением флага `is_freelance_or_part_time = True`.

## 3. Алгоритм выявления накрутки стажа (`ExperienceVerifier`)

Движок `ExperienceVerifier` сопоставляет стаж, указанный в тексте резюме, с переданными ему внешними записями. Сами парсеры и расчёт расхождения ещё не подтверждают подлинность источника и принадлежность профиля кандидату.

1. **Расчёт заявленного стажа:**
   - Извлечение реальных дат начала и окончания работы из текста резюме с фильтрацией календарных годов (предотвращение ошибочной трактовки года `2024` как 2024 лет стажа).
   - Заявленный грейд не превращается в стаж. Если в резюме нет данных о продолжительности работы, результат сравнения — «недостаточно данных».
2. **Агрегация внешних источников:**
   - Формальные источники: Хабр Карьера и Careerist (`is_freelance_or_part_time = False`).
   - Фриланс-источники: Профи.ру (`is_freelance_or_part_time = True`).
3. **Критерии присуждения статуса «возможно крутит опыт»:**
   - **Критерий 1 (Масштабное расхождение стажа):**
     Заявлен стаж $\ge 36$ месяцев (Middle/Senior), при этом в формальных внешних профилях подтверждено $< 18$ месяцев и разрыв составляет $\ge 24$ месяцев, либо заявленный стаж превышает внешний более чем в 2 раза при разрыве от 2 лет.
   - **Критерий 2 (Аномальный сдвиг старта карьеры):**
     Кандидат заявляет непрерывный опыт с 2018–2019 года, тогда как первая подтверждённая запись в профессиональных реестрах датируется 2023–2024 годом (сдвиг от 3 лет).
4. **Исключение для Профи.ру:**
   - Если у кандидата есть активность на Профи.ру, она добавляется в `freelance_experience_months`.
   - Наличие фриланса или репетиторства на Профи.ру **никогда не переводит кандидата в статус «возможно крутит опыт»**.

## 4. Архитектура защиты приватности кандидата (Privacy by Design)

Требование ТЗ: **«Сам кандидат не будет видеть, что система присудила ему статус 'возможно крутит опыт'»**.

Архитектурная реализация:
1. **Разделение моделей ответа (DTO Segregation):**
   - Для кандидата: модель `CandidateSanitizedAuditView` и стандартный профиль `CandidateProfileResponse`. В них **полностью отсутствуют** поля `status = "возможно крутит опыт"`, `is_flagged_for_inflation`, `reasons`, `discrepancy_months` и `flags`. Кандидат видит лишь нейтральную отметку о наличии внешних данных.
   - Для работодателя: модель `ExperienceVerificationAudit` с полным отчётом, предупреждениями и рекомендациями для собеседования (`employer_guidance`).
2. **Разграничение доступа на уровне эндпоинтов (RBAC):**
   - Эндпоинт `GET /api/v1/employer/candidates/{candidate_id}/experience-audit` защищён зависимостью `get_current_employer`.
   - При попытке вызова со стороны соискателя API возвращает **`403 Forbidden`** (`Недостаточно прав. Требуется роль: employer`).
3. **Скоринг доверия (`trust_score_service`):**
   - Метод `calculate_trust_score(candidate, for_employer=...)`:
     - При вызове для соискателя (`for_employer=False`) подозрительный флаг «Внешний опыт» **не добавляется**.
     - При вызове для работодателя (`for_employer=True`) работодатель видит флаг с предупреждением `status: "warning"`, `detail: "Возможно крутит опыт: заявленный стаж расходится с внешними источниками"`.

## 6. Результаты тестирования

Все модули покрыты автоматическими тестами в `backend/tests/test_b41_external_parsers.py`:

- `test_habr_career_api_payload_parsing`: парсинг структуры API Хабра.
- `test_habr_career_html_parsing`: парсинг HTML-профиля Хабр Карьеры с датами и навыками.
- `test_careerist_access_and_terms_check`: проверка условий использования Careerist и запрета обхода капчи.
- `test_careerist_catalog_parsing`: парсинг каталога программистов на Careerist.
- `test_careerist_cv_detail_parsing`: разбор детального резюме.
- `test_profi_ru_policy_and_tutoring_protection`: гарантия неприменения санкций за репетиторство.
- `test_profi_ru_catalog_and_profile_parsing`: парсинг анкет специалистов Профи.ру.
- `test_verifier_honest_candidate`: верификация честного кандидата (статус «расхождений не найдено»).
- `test_verifier_inflated_experience_detected`: детекция завышения стажа (статус «возможно крутит опыт»).
- `test_verifier_profi_ru_tutoring_does_not_flag_inflation`: гарантия отсутствия ложных срабатываний из-за Профи.ру.
- `test_candidate_never_sees_inflated_experience_status`: подтверждение скрытия статуса от соискателя.
- `test_trust_score_hides_suspicion_flag_from_candidate`: проверка скрытия подозрительного флага в True Score.
- `test_experience_audit_endpoint_permissions`: проверка запрета доступа кандидатам (403 Forbidden) и успешного ответа работодателю (200 OK).
