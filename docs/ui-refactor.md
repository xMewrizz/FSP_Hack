# Дизайн-спецификация интерфейса FSP Hack

Готовый промт и решения по экранам. Цель: единая типографика, сетка 16px, понятные грейды и визуальные якоря без «случайных» страниц.

---

## Промт для генерации и правок

Ты — Senior UX/UI-дизайнер и Frontend-архитектор (React/Tailwind CSS). Твоя задача — привести к единому, чистому и читаемому виду весь интерфейс платформы-агрегатора вакансий (FSP Hack). Проект на стеке: Vite + React + Tailwind + FastAPI.

### Главная цель

Убрать визуальный шум, сделать типографику предсказуемой, вернуть понятную иерархию и добавить визуальные якоря (иконки, графические элементы).

### Критические требования (обязательно реализовать)

**1. Единая типографическая система (никаких «гигантских» и «крошечных» шрифтов):**

- Базовый размер текста: `16px` (или `text-base` в Tailwind).
- Заголовки экранов: `24–28px` (`text-3xl`).
- Подзаголовки/названия блоков: `20px` (`text-xl`).
- Мелкие подписи, статусы, «Есики»: `13–14px` (`text-sm`).
- Текст кнопок: строго `16px`, не меньше.
- Запрещено: использовать размеры меньше 14px для основного текста и больше 32px для заголовков без явной причины.

**2. Отступы и сетка (чтобы не было «сплошником» и «на рандом»):**

- Использовать базовый шаг `16px` (в Tailwind это `p-4`, `py-4`, `px-4`, `gap-4`).
- Между крупными блоками (карточки, секции) отступ минимум `32px` (`py-8` / `gap-8`).
- Внутри карточки между заголовком, текстом и кнопкой — `16–24px`.
- В формах (загрузка PDF, согласия) — явные отступы вокруг полей и кнопок, никаких «склеиваний».
- Для PDF-блока: сделать явную визуальную связь «согласие → доступ к файлу» (иконка замка/разблокировки, короткий текст-подсказка).

**3. Многоугольники навыков (грейды/уровни) — сделать их понятными:**

- На всех экранах (каталог, вакансии, профиль) реализовать единый компонент «многоугольник навыков» (radar chart / skill polygon).
- Вершины многоугольника: ключевые навыки (например, SQL, Python, Git, Agile).
- Цвет заливки: полупрозрачный, акцентный цвет бренда. Контур — более тёмный.
- Рядом с многоугольником — 2–3 самых сильных навыка текстом (крупно) и 2 слабых (мелким текстом, как зона роста).
- Если уровень подтверждён — добавить бейдж «Подтверждено» с галочкой. Если нет — «Требуется тест» с иконкой вопросительного знака.

**4. Иконки и визуальные якоря:**

- Добавить иконки ко всем ключевым действиям (кнопка «Загрузить PDF» → иконка PDF/загрузки; «Подтвердить email» → иконка письма; «Пройти тест» → иконка теста).
- К каждому статусу (например, «Грейд не подтверждён», «Ожидает проверки») — маленькая иконка слева.
- Убрать «стены текста»: если на экране больше 5 строк сплошного текста — разбить на пункты с буллетами или карточками.

**5. Логика экранов (что должно быть понятно с первого взгляда):**

- **Экран загрузки PDF и согласия:** показать 2 шага: «1. Принять условия → 2. Скачать/загрузить». Сделать кнопку неактивной, пока не стоит галочка.
- **Экран теста (проверка после задания):** убрать текст, который дублирует очевидное. Оставить только: «Результат», «Оценка», «Что улучшить» (с иконками). Текст слева от кнопки — либо удалить, либо перенести в подсказку (tooltip).
- **Кабинет (уровень):** разделить на 2 понятных блока: «Заявленный уровень» (серый фон, нейтральный текст) и «Подтверждённый уровень» (акцентный цвет, иконка галочки). Убрать огромные кнопки — сделать их стандартной ширины и высоты, не растягивать на всю ширину без причины.
- **Каталог/Вакансии:** везде одинаковый паттерн: иконка → заголовок → многоугольник навыков → кнопка действия. Никаких «плавающих» элементов.

**6. Адаптив и десктоп:**

- На десктопе: колонки 2–3 в ряд, одинаковые отступы.
- Никаких скачков размера шрифта при переходе между экранами.
- Все экраны должны выглядеть как часть одной системы, а не как набор случайных страниц.

### Важные нюансы продукта

- Рядом с зарплатой всегда подпись `до вычета НДФЛ` или `на руки` (`text-sm`, приглушённый цвет). Это требование жюри.
- Если полноценный SVG-радар уже есть — использовать его; иначе допустимы полоски прогресса 3–5 навыков.
- Иконки: существующий SVG-набор в `App.tsx` (стиль Lucide), без обязательной новой зависимости.

2. Многоугольники навыков + логика грейдов (компонент `SkillMap`).
3. Иконки + чистка лишних текстов на пяти экранах ниже.

## Решения по экранам

Классы ниже — ориентир. В проекте канон задаётся CSS-переменными: `--fs-base: 1rem`, `--fs-heading: 1.25rem`, `--fs-title: 1.625rem`, `--space-2: 1rem`, `--space-4: 2rem`.

### 1. Загрузка PDF + согласие (Профиль)

**Проблемы**

- Блок загрузки и кнопка PDF склеены со стеной пояснения.
- Нет связи «согласие → файл»: кнопка просто `disabled`.
- Нет шагов и иконки замка.

**Классы**

- Карточка: `flex flex-col gap-4 p-6`
- Шаги: `grid grid-cols-2 gap-4`
- Подсказка: `text-sm text-[var(--muted)]`
- Кнопка: `inline-flex gap-2` (не `w-full`)

**Тексты**

- Кнопка загрузки: «Загрузить PDF»
- Кнопка скачивания: «Скачать профиль» / «Сначала примите условия»
- Подсказка: «После согласия файл откроется. Контакты в PDF не входят.»

**Компоновка**

Верх — заголовок «Резюме». Далее две ступени в ряд: 1) согласие с чекбоксом, 2) загрузка/скачивание. Снизу — зона dropzone и превью распознанных данных.

### 2. Профиль / кабинет уровня («Мой грейд»)

**Проблемы**

- Заявленный и подтверждённый уровни смешаны в одном герое.
- Кнопки растягиваются на всю ширину карточки.
- Многоугольник не объясняет сильные и слабые навыки.

**Классы**

- Пара карточек: `grid grid-cols-2 gap-4` (`gap-8` между секциями)
- Заявленный: нейтральный фон `--surface-soft`
- Подтверждённый: акцент `border-[var(--violet)]` + бейдж
- Кнопка: `w-auto min-h-11 text-base`

**Тексты**

- «Заявленный уровень» / «Подтверждённый уровень»
- Бейдж: «Подтверждено» / «Требуется тест»
- Кнопка: «Пройти тест»

**Компоновка**

Верх — две карточки уровня в ряд. Ниже — многоугольник навыков + сильные/зона роста. Затем история тестов.

### 3. Каталог / вакансии

**Проблемы**

- Нет единого паттерна карточки.
- Зарплата без пометки НДФЛ спорит с основным текстом или теряется.
- Радар есть не везде, отступ до кнопки случайный.

**Классы**

- Карточка: `flex flex-col gap-4 p-6 rounded-xl`
- Заголовок: `flex items-center gap-4` + иконка 40px
- Зарплата: основная сумма `text-base font-semibold`, подпись `text-sm` muted
- Кнопка внизу, `mt-auto`, стандартная ширина

**Тексты**

- «Откликнуться» / «Отклик отправлен» / «Открыть вакансию»
- Подпись: «до вычета НДФЛ» или «на руки»

**Компоновка**

Иконка компании → заголовок и грейд → многоугольник → зарплата с подписью → кнопка.

### 4. Результат теста

**Проблемы**

- Длинный текст дублирует заголовок и оценку.
- Слева от кнопки фраза «Проверка — после последнего задания» не объясняет действие.
- Нет трёх ясных блоков.

**Классы**

- Оболочка: `flex flex-col gap-6 p-6 text-left` (не центр на всю ширину)
- Три карточки: `grid grid-cols-3 gap-4` (на узком экране 1 колонка)
- Футер: только кнопка справа, пояснение в `title`

**Тексты**

- Результат: «Навык сохранён» / «Грейд подтверждён» / «Грейд не подтверждён»
- Оценка: «N из M верно»
- Улучшить: 1–3 темы с ошибками
- Кнопка: «К навыкам» / «Далее» / «Завершить»

**Компоновка**

Верх — заголовок «Результат». Три карточки в ряд. Ниже разбор по желанию. Кнопка отдельно, без текста слева.

### 5. Приватность / настройки

**Проблемы**

- Отступы между строками статуса, чекбоксами и кнопкой разные.
- Статусы без иконок.
- Нет визуальной иерархии согласий.

**Классы**

- Колонки: `grid grid-cols-2 gap-8`
- Внутри карточки: `flex flex-col gap-4`
- Строка статуса: `flex items-center gap-3 min-h-11`
- Согласие: `flex gap-4 p-4 rounded-xl border`

**Тексты**

- «Профиль виден работодателям» / «Скрыт»
- «Сохранить видимость»
- ФСП: «Привязать ID» вместо «Найти»

**Компоновка**

Слева — приватность (статусы, два согласия, кнопка). Справа — ФСП ID. Одинаковые внутренние отступы `p-6` и `gap-4`.
