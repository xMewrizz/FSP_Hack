# B-25: проверка заданий с кодом

В репозитории есть банк скрытых тестов и прототип проверки кода. Прежний вариант запускал ответ кандидата подпроцессом backend: AST-фильтр и таймаут не ограничивали доступ к файлам, сети и памяти. Запуск этого варианта из пользовательских маршрутов убран.

Подготовлен отдельный Docker-исполнитель. Контроллер принимает 11 из 13 заданий с кодом из текущего банка, включая Backend и Data Science; для каждого пробного запуска создаёт новый контейнер. Одновременно могут выполняться не более двух попыток. Пока не покрыты два задания пересдачи Senior: одно допускает псевдокод и не имеет исполняемого контракта, другое не задаёт сигнатуру функции и формат результата. Пробный запуск проверяет поведение на изменяемых входных данных, но не заменяет оценку архитектурных решений и риска утечки данных по критериям задания.

Внутри контейнера код кандидата работает с правами отдельного пользователя. Ожидаемые ответы вычисляет другой процесс, который выбирает новые входные данные для каждой попытки. Кандидатский код получает входные данные, но не ожидаемые ответы. Старые фиксированные тесты остались в репозитории для локальной проверки прототипа; рабочий исполнитель их не использует. Контейнеру запрещена сеть, файловая система доступна только для чтения, временная директория ограничена по размеру. Ограничены память, CPU и число процессов. Контейнер не получает переменные backend и тома с базой. Для задач Data Science отдельный образ содержит NumPy, Pandas и scikit-learn; число вычислительных потоков ограничено. Кандидат видит число пройденных проверок без названий тестов и вывода процесса. Свои тесты через API отправить нельзя.

Исполнитель включается отдельным профилем Compose: `docker compose --profile sandbox up --build -d`. Для backend задайте `SANDBOX_SERVICE_URL=http://sandbox-controller:8002` в локальном `.env` и пересоздайте backend. Если профиль выключен или исполнитель недоступен, маршруты `/testing/code-sandbox/execute` и `/testing/open-questions/{code}/test-run` отвечают `503`. При отправке обязательного задания код сохраняется, а модель оценивает его в фоне; при сбое модели кандидат может повторить проверку сохранённого ответа. Backend сам этот код не исполняет.

Сквозная проверка на работающем Docker прошла для эталонных решений всех 11 поддерживаемых задач, неверного ответа, подделки строки результата, бесконечного цикла, попытки выделить слишком много памяти и отказа для неподдерживаемого задания. Дополнительно проверены отсутствие Docker-сокета, сети, секретов и привилегий у процесса кандидата, сохранение работоспособности исполнителя после ошибки и удаление контейнеров после попыток. Рабочий итоговый балл открытого задания сейчас выставляет модель; результат контейнера доступен как пробный запуск. Доступные в репозитории алгоритмы генерации проверок не следует считать секретом; повторение и обмен ответами учитываются отдельно при разработке теста на грейд.
