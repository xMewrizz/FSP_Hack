# B-25: проверка заданий с кодом

В репозитории есть банк скрытых тестов и прототип проверки кода. Прежний вариант запускал ответ кандидата подпроцессом backend: AST-фильтр и таймаут не ограничивали доступ к файлам, сети и памяти. Запуск этого варианта из пользовательских маршрутов убран.

Подготовлен отдельный Docker-исполнитель. Контроллер принимает только два Backend-задания (`OPEN-BE-CODE-01`, `OPEN-BE-CODE-02`) и создаёт новый контейнер для каждой попытки. Одновременно могут выполняться не более двух попыток. Проверка Data Science пока не открыта: прежние тесты проверяют лишь наличие функции, а не правильность вычислений.

Внутри контейнера код кандидата работает с правами отдельного пользователя. Ожидаемые ответы вычисляет другой процесс, который выбирает новые входные данные для каждой попытки. Кандидатский код получает входные данные, но не ожидаемые ответы. Старые фиксированные тесты остались в репозитории для локальной проверки прототипа; рабочий исполнитель их не использует. Контейнеру запрещена сеть, файловая система доступна только для чтения, временная директория ограничена по размеру. Ограничены память, CPU и число процессов. Контейнер не получает переменные backend и тома с базой. Кандидат видит число пройденных проверок без названий тестов и вывода процесса. Свои тесты через API отправить нельзя.

Исполнитель включается отдельным профилем Compose: `docker compose --profile sandbox up --build -d`. Для backend задайте `SANDBOX_SERVICE_URL=http://sandbox-controller:8002` в локальном `.env` и пересоздайте backend. Если профиль выключен или исполнитель недоступен, маршруты `/testing/code-sandbox/execute` и `/testing/open-questions/{code}/test-run` отвечают `503`. Подача открытого ответа через `/submit` сохраняет код и оценивает его моделью; при сбое модели код не исполняется в backend и работа требует ручной проверки.

Локальный Docker Desktop пока не поднимает движок. Сквозная проверка подготовлена в `.github/workflows/b25-sandbox.yml`: она запускает рабочий Compose-исполнитель и проверяет правильные решения, неверный ответ, подделку строки результата, превышение времени и отказ для неподдерживаемого задания. B-25 можно закрыть после успешного прогона этого сценария и проверки изоляции на работающем Docker. Доступные в репозитории алгоритмы генерации проверок не следует считать секретом; для подтверждения грейда нужны отдельные меры против повторения и обмена ответами.
