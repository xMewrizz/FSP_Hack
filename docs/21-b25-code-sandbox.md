# B-25: проверка заданий с кодом

В репозитории есть прототип проверки кода: фильтр AST, подпроцесс с таймаутом и скрытые тесты для трёх заданий. Его тесты показывают, что он умеет проверять ожидаемые решения и останавливать обычный бесконечный цикл. Это **не изолированная песочница**: подпроцесс работает с правами backend, фильтр AST можно обойти, лимита памяти и запрета сети нет. Передавать в него код кандидата нельзя.

Публичные маршруты `POST /testing/code-sandbox/execute` и `POST /testing/open-questions/{code}/test-run` отвечают `503`. При отправке открытого задания с кодом ответ сохраняется и может получить оценку от LLM. Если модель недоступна, backend не запускает код: результат помечается для ручной проверки. Код прототипа и его тесты оставлены как материал для разработки отдельного исполнителя.

Чтобы закрыть B-25, нужен исполнитель вне backend, который запускает каждый ответ в отдельной среде без доступа к базе, ключам, сети и другим ответам. Для него нужно ограничить память, CPU, время и число процессов, а также проверить побег из среды и подделку результатов. Скрытые тесты и их ключи должны храниться вне окружения исполняемого кода. После интеграции следует повторить проверку через работающий Compose и только тогда включить маршруты.
