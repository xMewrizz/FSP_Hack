# B-25: проверка заданий с кодом

В репозитории есть банк скрытых тестов и прототип проверки кода. Прежний вариант запускал ответ кандидата подпроцессом backend: AST-фильтр и таймаут не ограничивали доступ к файлам, сети и памяти. Запуск этого варианта из пользовательских маршрутов убран.

Подготовлен отдельный Docker-исполнитель. Контроллер принимает только два Backend-задания с проверяемыми тестами (`OPEN-BE-CODE-01`, `OPEN-BE-CODE-02`) и создаёт новый контейнер для каждой попытки. Одновременно могут выполняться не более двух попыток. Проверка Data Science пока не открыта: установленный в образе банк проверяет лишь наличие функции, но не правильность вычислений. Контейнеру запрещена сеть, файловая система доступна только для чтения, временная директория ограничена по размеру. Ограничены память, CPU и число процессов; код кандидата запускается с отдельным UID. Контейнер не получает переменные backend и тома с базой. Кандидат видит число пройденных проверок без названий тестов и вывода процесса. Собственный код скрытых тестов через API отправить нельзя.

Исполнитель включается отдельным профилем Compose: `docker compose --profile sandbox up --build -d`. Для backend задайте `SANDBOX_SERVICE_URL=http://sandbox-controller:8002` в локальном `.env` и пересоздайте backend. Если профиль выключен или исполнитель недоступен, маршруты `/testing/code-sandbox/execute` и `/testing/open-questions/{code}/test-run` отвечают `503`. Подача открытого ответа через `/submit` сохраняет код и оценивает его моделью; при сбое модели код не исполняется в backend и работа требует ручной проверки.

Код контроллера и настройки контейнера проверены тестами, но работающий Docker в текущем окружении не поднялся, поэтому сквозной запуск не подтверждён. Закрыть B-25 можно после прогона через Compose и проверки попыток выйти из контейнера, исчерпать память и подделать результат. Скрытые тесты сейчас лежат в исходном коде: после публикации репозитория они будут видны его читателям. Перед использованием для подтверждения грейда закрытые варианты и ключи надо хранить отдельно от публичного кода.
